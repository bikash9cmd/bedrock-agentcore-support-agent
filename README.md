# Customer Support Agent on Amazon Bedrock AgentCore

A production-style AI customer support agent built end to end on **Amazon Bedrock AgentCore** with the **Strands Agents SDK** and **Claude Sonnet 4.6**. It answers product and return-policy questions, remembers customers across sessions, calls back-end tools through a secured gateway, and is governed, evaluated and A/B tested like a real service rather than a demo.

## Features

- **Persistent memory:** a shared AgentCore Memory store, so a returning customer doesn't start from zero.
- **Tools through AgentCore Gateway:** warranty and refund tools exposed over MCP behind an OAuth-secured gateway, plus local tools for return policy and product info.
- **Authentication:** the Runtime and Gateway both require Cognito JWTs.
- **Policy governance:** a Cedar policy engine enforces business rules (for example refund limits) outside the agent code, with semantic guardrails on sensitive inputs.
- **Continuous evaluation:** online LLM-as-judge quality monitors on live traffic.
- **A/B testing:** control and treatment config bundles on two runtimes (`CustomerSupport`, `CustomerSupportAB`) with statistically validated comparison before promotion.
- **Zero-code harness agents:** `OrderResearchAgent`, `PersistentReportAgent` and `ContainerAgent`, defined only by config and a system prompt.
- **Observability:** every invocation traced through OpenTelemetry.
- **Chat UI:** a small web front end in `app/CustomerSupport/frontend`.

## Tech stack

| Area | Tools |
|---|---|
| Agent framework | Strands Agents SDK (Python) |
| Model | Claude Sonnet 4.6 on Amazon Bedrock |
| Platform | Amazon Bedrock AgentCore (Runtime, Memory, Gateway, Identity, Policy, Evaluations) |
| Auth | Amazon Cognito (JWT) |
| Infrastructure | AWS CDK (TypeScript) via the AgentCore CLI |
| Tooling | uv, Node.js, AWS CLI |

## 🚀 Getting Started

> This project was built as part of the **[Getting Started with Amazon Bedrock AgentCore](https://catalog.workshops.aws/agentcore-getting-started/)** AWS workshop.

### Prerequisites
- Node.js 20+, `uv`, AWS CLI v2, Git
- AWS account with Bedrock model access (Anthropic use-case form submitted)
- AWS region: `us-east-1` or `us-west-2`

### Setup
```bash
npm install -g @aws/agentcore@0.22.0
aws configure
agentcore create --name CustomerSupport --framework Strands --model-provider Bedrock --memory none
cd CustomerSupport
agentcore deploy -y -v
```

Full step-by-step setup, including memory, gateway, JWT auth, policies, and the chat UI, is documented across the labs referenced above.

## 🔐 Security Notes

- All credentials, tokens, and `.env.local` files are excluded via `.gitignore`
- The Runtime and Gateway are secured with Cognito JWT authentication
- Sensitive tool inputs (e.g., email addresses in refund reasons) are blocked via semantic policy guardrails
- This repository contains **no live credentials** — reproduce by provisioning your own AWS resources

## 📈 What I Learned

Building this reinforced a few things about production agentic systems:
- **Memory is what separates a demo from a product** — without it, every conversation starts from zero.
- **Governance belongs outside the agent** — Cedar policies enforce business rules at the infrastructure boundary, so agent code never needs to "know" about spending limits.
- **Observability shouldn't be an afterthought** — every invocation here is automatically traced via OpenTelemetry, with zero manual instrumentation.
- **Optimization should be evidence-based** — the A/B testing pipeline validates prompt changes with real statistical significance before promotion, not gut feeling.
